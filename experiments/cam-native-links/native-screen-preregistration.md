# Prospective CAM native-kernel headroom screen — DRAFT, NOT EXECUTED

This screen can return HOLD or justify a later separately frozen integration experiment. It cannot pass the pursuit rubric. No Detour planner is implemented here. It tests whether a narrowly defined existing CAM computation leaves enough observable work to justify that build.

## Claim, buyer, and scope

The possible purchased deliverable is integration/support for repeated FreeCAD adaptive roughing preparation. The proposed practical benefit is reduced regeneration work or fewer unnecessary retract links under the same native length/clearance constraints. Advertised CAM programming prices and existing paid CAM products establish a category only (see SCREEN.md); no customer has agreed to pay and no shop workload has been obtained.

This is a planar **native Adaptive2d kernel** experiment using footprints from a licensed upstream FCStd fixture. It is not a full FreeCAD/OCC job replay. It does not establish the same cutting sequence as FreeCAD's feature extraction, 3D stock transitions, machine collision clearance, actual machining time, finish, or human labor saved. No G-code will be produced for machine use.

## Instrumentation and equality

Only the sole ResolveLinkPath call site inside FindLinkPath is wrapped: save a begin record containing exact current cleared polygons, integer scale, radius, stepover, ratio and endpoints (including Clipper1 Z tag payloads preserved separately from XY; these tags are not physical height) **before** calling the original function; save its result/path after return. ResolveLinkPath and its clock-based stopping code remain byte-identical. Logging never occurs inside its timed search. Kernel progress callback always returns false (no cancellation); stopProcessing is explicitly false in isolated replay and reset false by native Execute in full runs. GetCleared returns the already maintained polygon vector; it does not compute the final CAD model or reconstruct stock retrospectively.

An access-only adapted header makes private members public for isolated replay. Original executable function bodies remain unchanged. Every adapted file, patch generator, driver and source will be hashed before execution. The actual plain/capture binary hashes are also pinned and verified in the private execution source-freeze record; binaries are not published. Native baseline measurements use a separate build with no trace calls. Instrumented data acquisition time is reported separately, never attributed as original native computation.

Run one trace acquisition per workload, then three no-logging full-kernel runs in fresh processes. Compare the complete native output structures (all paths/motion types, relevant coordinates, cleared area, scale, and error flags), excluding timings/debug messages. All no-logging repeats must agree with the traced output. Any timeout-sensitive divergence, native error flag, crash, unsupported input or incomplete trace is retained and makes that workload invalid for affirmative headroom claims; do not tune its cap/settings to repair the outcome.

Replay every completed captured ResolveLinkPath request through the original function with its exact historic stock and state, without logging, three times in fresh initialized native objects. Compare result booleans and successful output path coordinates and Clipper Z tags with the capture. Report failures, durations and any nondeterminism. Replay work is a profile of isolated native link calls, not an additive guarantee of whole-job speedup. No-logging kernel timings provide the actual total native baseline; trace, extraction, replay and oracle costs are separately reported.

## Conservative endpoint subset and strong simple baseline

Native endpoint treatment is direction dependent: the original routine skips portions near its endpoints, normally uses stepover as extra clearance, and sets that clearance to zero for short requests. Preserve these facts in metadata. The screen does not emulate or weaken them to gain feasibility.

A link is eligible for the geometric baseline only if its two full endpoint disks fit a conservative center-space polygon at radius `native_tool_radius + native_clearance + 2 native integer units`, where native_clearance equals stepover unless the native short-link rule makes it zero. Shrink the captured cleared area using the bundled Clipper1 closed-polygon round offset with explicit arc tolerance0.25 integer units. The extra2 integer units cover polygonal/rounding approximation for this conservative study; final candidate links must additionally pass the independent continuous segment clearance check below. Both endpoints must lie in the same connected center-space component. All ineligible requests retain their original native outcomes/cost and exact exclusion reasons.

For a manageable eligible component, build the complete visibility graph of all its polygon vertices plus endpoints. Edges must stay within that same closed polygon (holes excluded); use Dijkstra with Euclidean edge weights. This is the shortest path on that complete polygon visibility graph, not a claim of exact globally shortest path in the original curved cutter configuration space. No mesh planner receives an advantage from a weaker geometry or endpoint policy. A later Detour comparison would use the same center-space representation and charge every stock-state rebuild.

Apply the original ratio3 limit to the complete returned path. Independently verify every returned segment against the un-eroded recorded cleared polygon: exact integer orientation/intersection checks and rational squared point-to-segment distances must establish whole-segment containment and clearance at least the native radius+clearance. Native IsClearPath with full, untrimmed segments is an additional check, not the sole verifier. Unsupported/invalid topology, nonfinite values, graph disconnection, truncated search, insufficient margin, or a failed verifier yields no valid witness.

Native paths are reported both under their original endpoint policy and under this stronger complete-segment verifier. Do not relabel an original endpoint-policy success as a native safety defect. A recovered-link witness requires original native failure plus a fully verified graph path within its ratio budget. These calls also include engagement/lead proposals that may never be selected by the enclosing kernel. Recovery is therefore proposal-level headroom, NOT a measured reduction in final retracts. All final-output benefits require a later integrated comparison.

## Resource limits and prospective selection

Each kernel process:30s wall limit and2GiB RSS, 64MiB trace limit, at most10,000 link records. All six workload outcomes are retained, including censoring. Total native acquisition/control/replay wall budget:600s. Execution reserves1s of that limit for final summary serialization (operational deadline599s); the300s geometry phase likewise uses299s plus1s reserve. Check actual elapsed time after each phase and its last serialization, not only before subprocesses. If final summary serialization exceeds the reserve, HOLD. RSS is the cumulative observed maximum of the orchestrator and completed subprocesses; child virtual address space is also capped at2GiB. Stop with HOLD_RESOURCE_LIMIT if exhausted; no larger workload is substituted.

Every captured request is counted. Geometry screening may inspect all records, but the complete graph is limited to components with at most128 vertices and at most4,096 original stock boundary edges. Within each workload, evaluate the first16 eligible non-straight requests in native call order (at most96 total). A request is non-straight if the direct segment fails the same complete-segment native-clearance verifier. The300s geometry budget charges ALL eligibility erosion, component/containment tests and direct-segment checks, including rejected/censored requests; it is not restricted to selected graph solves. Requests beyond those fixed limits are explicitly censored, never silently discarded. Full graph phase:5s/request and300s total, including erosion, graph construction, path search, and verification. Repeated source/source-state hashes are recorded; no uncharged caching is assumed.

## Decision rule

CONTINUE_TO_SEPARATE_PROTOCOL requires valid equality/replay controls for ALL six workloads and ALL captured requests (any incomplete native control or unplanned global resource abort causes global HOLD; prospectively limited graph selection/vertex exclusions are counted but do not by themselves invalidate the screen), at least10 eligible non-straight requests spanning at least two of the six configurations, and at least one of:

1. The sum of median isolated native replay CPU_seconds costs for all eligible requests exceeds1s and20% of the sum of median no-logging full-kernel CPU_seconds times. This is an exploratory profile warranting an actual end-to-end comparison, not a measured achievable saving.
2. The fixed graph sample recovers at least three original native failures with verified paths, spanning at least two configurations.

Otherwise HOLD_INSUFFICIENT_HEADROOM. Resource or correctness failures yield HOLD with the relevant reason. Counts across configurations are not independent customer/part samples: all derive from one upstream regression fixture. A passing headroom screen still requires more representative lawful inputs, a real essential Detour bridge, end-to-end strong-baseline measurement, exact rights audit, and independent commercial judgment under the unchanged pursuit rubric.

Before costly geometry work, a mathematical negative screen is allowed: if even ALL captured request replay CPU fails the1s/20% profile condition, and ALL native failed proposals cannot meet the three-failures/two-configurations recovery condition, return HOLD_NATIVE_CEILING without geometric evaluation. This upper bound is conservative because eligibility can only remove requests. It cannot affirm continuation.

Geometry controls are frozen in visibility-oracle.py: exact point/segment distance, full-disk and zero-length cases, a hole-crossing case, tangent/collinear visibility, known small visibility-graph length, disconnected components, nested islands, nonzero-area self-crossing rings, and touching-ring rejection. Topology is checked on original and center-space rings: simple rings, disjoint boundaries (touching rejected), parity-consistent orientation and nesting. Reject rather than repair unsupported topology. Coordinate values must be integers of magnitude at most2^50; radius/scale positive integers, ratio/stepover finite positive numbers. The4,096 stock-edge bound is a planned geometry scope exclusion applied before expensive topology checks, with unknown eligibility explicitly recorded. Profile cost excludes such requests.

No scores, thresholds, inputs or endpoint policies change after execution. A later refinement is a new prospective experiment with preserved original outcomes.
