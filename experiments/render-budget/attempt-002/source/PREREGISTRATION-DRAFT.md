## Claim and limits

Can joint rendered-error allocation select per-texture standard texture encodings with materially better held-out rendered fidelity than competent presets and render-aware greedy allocation under the same GLB-byte ceiling and configuration-evaluation budget?

Business hypothesis: a web 3D production agency could use a reproducible, local batch export and acceptance packet when preparing customer product catalogs. Primary measured outcomes are real deliverable bytes and image error in a named browser renderer. Neither metric establishes human-perceived equivalence, customer savings, runtime speed, cross-device fidelity, or superiority to untested paid software.

## Algorithms and equal-budget comparison

All methods may share the source/encoded option files and deterministic original references. A rendered configuration costs six images, even if a cache makes replay cheap. Each search method receives **256 distinct six-view configuration evaluations per asset per byte budget**; repeated configurations count once within that method. The same configuration evaluated by multiple methods counts toward each method's allowance. Each search receives identical preset candidates, but their evaluations count within its 256 allowance. No method sees another's adaptive results, and held-out images never guide selection. Wall time is separately reported; equal calls are not a claim of equal CPU/GPU time.

1. **Channel-aware preset sweep:** all combinations of one resolution fraction for color images and one for noncolor images (three each), with ETC1S color/UASTC noncolor; plus uniform all-ETC1S, all-UASTC and all-WebP at each fraction, a WebP-nonnormal/original-normal strategy at each fraction, and unchanged original. Evaluate every feasible distinct preset. Select minimum training loss. Also report the published FlightHelmet ETC1S/UASTC full-resolution recipe whether feasible or not.
2. **Texture-domain allocation:** decode each candidate to RGBA (KTX via the pinned `ktx extract --transcode rgba8` command), upsample to source dimensions with Lanczos3, and compare consumed channels only. Color/emissive RGB errors are normalized MAE on stored channel values, including alpha when consumed. ORM uses the union of actually consumed R/G/B channels; standalone occlusion/clearcoat uses R. A normal map contributes mean `acos(clamp(dot(normalize(2*sourceRGB-1), normalize(2*candidateRGB-1)))) / pi`, plus alpha error if consumed, averaged across those terms. A zero normal vector maps to (0,0,1). For images serving multiple compatible roles, average the normalized role distortions. Begin with the smallest-payload option for every image and upgrade by largest positive distortion decrease per added byte; error-reducing nonpositive-byte swaps take priority. Recompute after each choice. Ties use image index then option index. Return the final greedy allocation if it is feasible; otherwise report no feasible heuristic output. Evaluate its final configuration in the real renderer. Record its much cheaper computation; do not force it to waste calls.
3. **Render-aware greedy:** start from the best feasible member of the full common charged pool. The initial common charged pool comprises every feasible preset, the smallest combination, and every single-image substitution from that smallest combination, including over-budget calibration probes. Both greedy and CP-SAT receive this pool and are charged for it. All base errors and deltas refer to the smallest-payload vector, not the greedy current state. Over-budget calibration renders are charged but cannot be eligible winners. No option is removed solely because its individual probe exceeds the ceiling. Define per-view deltas `d(i,o,v)=error_v(smallest with image i at o)-error_v(smallest)`. If the pool exceeds 256, stop and report a protocol feasibility failure rather than truncate by index. At the current state evaluate feasible one-image substitutions in ascending predicted maximum view error `max_v(e0[v]+sum_i d(i,o_i,v))`, then byte size, then lexicographic vector. After a complete neighborhood, accept the greatest positive decrease in actual loss per added byte; improving nonpositive-byte substitutions take priority by absolute loss decrease. Stop at local optimum or 256 distinct evaluations. If capped mid-neighborhood, return the lowest-loss evaluated feasible configuration, never merely the last state. Greedy retains every evaluated preset as fallback and gets the same paid sensitivity ordering as CP-SAT.
4. **Joint candidate, OR-Tools CP-SAT:** use the same charged preset/smallest/single-substitution pool. For each view separately define base error `e0[v]` and single-image deltas `d[i,o,v]`. Image impact is the greatest decrease in six-view maximum loss among its paid single substitutions; ties use image index. Select the top three images, and for each select its two most beneficial non-start options by reduction in maximum loss per added byte (ties: lower bytes, then option index). Measure the joint combinations for each pair of these three images (including over-budget calibration probes, never eligible winners), at most twelve additional configurations. Pair correction for view v is `r[i,o,j,p,v] = actual_pair_error[v] - e0[v] - d[i,o,v] - d[j,p,v]`; unmeasured pair entries have zero correction. These are actual renders, charged to the candidate, not invented interaction terms.

   Construct one-hot binary choices `x[i,o]` and a pair conjunction variable for each measured correction. Minimize the maximum predicted six-view error `e0[v] + sum(d*x) + sum(r*pair)` subject to exactly one choice/image and a conservative GLB-byte constraint. Quantize each error coefficient with Python round at scale 10^6 (ties to even), preserving signs. Use OR-Tools CP-SAT 9.15.6755, one worker, random seed 9107, deterministic-time cap 2.0 and wall-time cap 10 seconds per solve (15-second IPC guard), and retain/report solver status, objective bound and quantization scale. The version has been installed and its artifact pins preserved. A persistent JSONL process imports OR-Tools once per search; each request constructs a fresh model with no solver state carried forward. All startup/solve wall time is charged.

   For byte coefficients use actual image payload lengths padded to four-byte alignment. `byte-bound.mjs` serializes the original and every single-option variant before search, asserts fixed array counts/order and unchanged remaining JSON fields, and constructs a conservative JSON length bound by selecting the maximum serialized entry length for each image and texture, using the union of required/used codec extensions, and replacing buffer lengths and shifted offsets by all-9 integers with the maximum finite total-payload digit width. Include GLB/chunk headers, JSON padding and unchanged nonimage binary bytes. Assert this bound's schema, topology and size against every subsequent actual serialization. The CP-SAT constraint is conservative and may exclude feasible outputs; its infeasibility is never treated as global infeasibility. Every proposal is actually serialized and checked against the true byte ceiling before it can become a feasible winner.

   Enumerate solutions through no-good cuts over option vectors, re-solving the fixed surrogate after every proposal. Each feasible new solution is actually rendered and charged; add no learned post-hoc correction other than the twelve preregistered pair measurements. Stop at 256 total paid configurations, no further solution, per-solve cap without a feasible solution, or the runtime cap. Return the feasible **actually rendered** configuration with lowest actual selection loss, not the surrogate winner by assertion. Compare to the strongest baseline on held-out renders. Report surrogate error on all enumerated configurations and whether interaction terms helped on the paired measurements; neither is a substitute for the held-out result. No algorithm claims depend on finding a CP-SAT optimality proof.

5. **Accessible SpatialPack texture-only recipe frontier:** run the unchanged npm `@spatialpack/core@0.1.0` public `runRecipeSearch` API in a separate comparator environment. For each of its three presets use `searchStrategy: 'grid'`, `searchDecimate: false`, `allowKtx2: true`, and its public `recipeOrdering` hook to retain recipes with `meshopt === false` and no decimation, preserving the approved-geometry scope. Across all three presets evaluate the complete filtered grids, with a combined maximum of 256 across the three presets. The preset and recipe together define a configuration because preset-specific encoding settings can differ; preserve raw grid cardinalities and reports. Identical output bytes may reuse render work but remain charged per distinct method configuration. Its public `qualityGate` hook evaluates the exact common six views and records actual bytes/loss; reject over-budget or structurally incompatible outputs. Select the best feasible rendered loss across all evaluated recipes, giving the comparator the best observed frontier rather than relying on a mismatched size-only winner. This is the actual implementation, not a rewritten approximation, but the comparator is explicitly **texture-only recipe search**, not SpatialPack's complete unconstrained product. Preserve its genuine codec fallbacks and report them. Record all calls/time; if legal/runtime access fails, report the missing comparator and do not claim a competitive pass. Its FSL core is not an implementation dependency or redistributed competing service. No source code is copied into the proposed mechanism.

For a fair strong baseline, the candidate may not use free individual-texture rendered sensitivities: every such configuration counts against its 256 allowance. Greedy receives the identical common paid initialization; the candidate's pair probes are charged separately. The original beam draft is archived, not run as an additional comparator. The cross-field transfer is the actual CP-SAT one-hot/minimax resource allocation, not post-hoc selection among already-scored files. Texture-only decoding cost is recorded; the inexpensive heuristic is not forced to waste renders. Report performance both against presets and against the best of all four baselines. Failure to beat render-aware greedy is informative even if the simpler render-aware integration beats presets.

## Checks and decisions

Before held-out evaluation: verify full-frame raw RGBA byte equality for original-versus-original for repeated deterministic renders and full-frame raw RGBA equality for original glTF-to-unchanged-GLB roundtrip; KTX outputs load without unsupported-extension/decoder errors; delivered GLB bytes meet ceilings; material/node/accessor invariants match; every referenced image is present; decoded accessor hashes and semantic geometry remain identical (raw binary layout may differ for the comparator). Name original source-image identities before serialization; verify the expected option payload hash for every named image and image identity at every material binding. Comparator transformations retain those source identity names and must pass the same binding/semantic checks; this is provenance through the unchanged comparator, not a claim of independent codec validation. Before any real asset reference, validate tiny authored asymmetric orientation, sRGB/data-channel, tangent-normal and alpha controls through the real encode/transcode/browser pipeline. Record whether GPU-compressed formats or RGBA fallback are used; do not claim GPU compression from a file extension. The authored texture controls are 64×64 asymmetric quadrant images, resized to 32×32 through the same encoding helper for color, data and tangent-normal roles and all three codecs; each decoded browser render must differ by at most 0.12 per normalized RGBA channel at four quadrant-center samples from its source render. Normal controls have opaque unused alpha. Also test a deliberately missing texture and an invalid KTX header to ensure render failures cannot receive a favorable score. These are harness controls, not candidate successes. Record setup failures and all attempts.

Search renders reuse actual transcoded textures in fixed materials for efficiency; they are not CPU image surrogates. Every sealed winner must be exported to a real standalone GLB, loaded anew with GLTFLoader/KTX2Loader, and match the search configuration’s full six RGBA image SHA-256 hashes exactly before any held-out evaluation.

Seal a JSON record of every method's final option vector, actual bytes, training loss, call counts and artifact hashes for all cells, then evaluate held-out views. Report all cells, including infeasible/failed ones.

**Technical support for the joint mechanism:** among feasible cells, candidate improves maximum held-out view error at least 15% relative to the strongest baseline in at least two cells from two different assets, while never increasing maximum held-out error more than 10% in any feasible cell. Require an absolute error reduction of at least 0.001 in winning cells so tiny floating-point differences cannot count. All integrity/byte checks must pass. These are prospective effect-size criteria for a small case study, not business proof.

If joint search fails, do not retune against held-out images. A render-aware-greedy result may be described honestly as a narrower finding, but it does not retroactively pass the joint claim. If every method is already near-lossless or preset-optimal at these budgets, report that the tested workflow does not need the new mechanism. No favorable subset or tightened byte budget replaces the frozen primary result.

Independent review should inspect actual GLB/KTX files, run a representative sealed output through the loader and recalculate its byte/error result. A second execution of the same renderer is a replay, not a second renderer or human quality validation.

## Runtime cap and censoring

Tiny-control encoding stage: 10 minutes. Per unique texture encode command: 120 seconds wall time, no automatic quality reduction on timeout. Total real-asset encoding stage: 40 minutes, enforced by absolute deadline checks and a killable process group. Per six-view configuration: 30 seconds after the initial shader/loader warm-up; a timed-out render is an error, not zero error. Per asset/budget method (preset sweep, texture-domain allocation, render-aware greedy, and CP-SAT): 15 minutes wall time in addition to applicable configuration limits. Check deadlines before/after serialization, before cached lookups, within neighborhood construction, and after the last evaluation; report final elapsed censoring even when no new render is attempted. The complete SpatialPack frontier has one 15-minute cap per asset. Any method’s time censoring makes the cell nonpassing. Entire experiment:3 hours effective elapsed excluding independent verification, including574.492 seconds original preprocessing plus actual attempt002 wall time; stop at the cap and retain all partial outcomes. Check elapsed time explicitly before and after final summary persistence as well as the process timer; crossing the cap cannot produce a passing summary. Source/schema readout and installation/build failures are setup evidence, not performance wins. Any cap-censored cell remains a nonpass for the primary criterion; do not drop it or rerun with a larger cap after held-out data have been seen. There is no automatic retry of a failure. An implementation bug found before held-out evaluation may be fixed only with the original code/output preserved and a recorded prospective amendment; a bug found after evaluation invalidates the affected result and requires a new protocol/data split.

All four selected models have OPAQUE/default-OPAQUE material modes. Alpha/orientation controls verify the pipeline, but this experiment does not validate alpha-cutout content or animated artifacts. If the originals render differently after the common serialization path, stop before optimizing.


## Frozen implementation notes

The authoritative code is the listed local source, published alongside this protocol. `run.mjs <new-freeze-commit>` verifies retained source/option/GLB/metadata hashes, runs fresh authored controls, shared original controls, selection, full-pixel exported-file checks, all-cell sealing, and only then held-out rendering. Attempt002 does not silently re-encode; its original encoding cost is charged explicitly. An error aborts the run and preserves a failure record; no failed output receives zero error. A configuration cache avoids duplicate physical renders, but each method is independently charged for every distinct configuration it requests. The common calibrations include over-budget probes because codec-dependent JSON overhead prevents safe option pruning; those probes never enter eligible winners.

Texture resources are disposed between assets and after loaded-file checks. The per-asset variant cache evicts inactive textures above 256 MiB of raw-equivalent mip storage and fails if live variants exceed 512 MiB; these are conservative resource estimates, not GPU memory claims. Renderer memory counters and actual internal compressed/RGBA formats are logged. A resource-censored cell is nonpassing. Child processes run in tracked process groups and are killed during timeout/failure cleanup; browser closes too. No measured throughput or commercial labor savings claim follows from this experiment.
