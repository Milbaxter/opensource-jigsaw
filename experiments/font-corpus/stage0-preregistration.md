# Prospective Stage0: font-corpus coverage ceiling

Status: prepared for parent publication and independent review; **not executed**. This stage can reject the proposed experiment cheaply. It cannot establish an OSS integration, practical advantage or a rubric-v2 pass.

## Decision and locked prospective benefit

The proposed purchased deliverable is a compact, executable corpus for font engineers checking configured OpenType feature behavior between releases. The transferable mechanism, if this screen leaves room, would combine FontTools program extraction, Z3 bounded GSUB execution and HarfBuzz replay. A separate working full-method draft exists but is not part of this Stage0 authorization or publication freeze.

The prospective technical benefit remains **at least10 additional native-effect-covered top-level calt lookups AND at least20% relative coverage improvement over the strongest equal-budget baseline on at least one primary font, with no coverage loss on the other**, using at most128 retained strings. This stage only tests whether even the existing project corpus leaves enough headroom. Do not change this metric to branch coverage, bug count or a speed metric after the ceiling result.

If the actually retained, budget-eligible baseline corpus (at most128 strings after common greedy selection) leaves fewer than10 total target lookups uncovered in **both** primary fonts, stop: the proposed minimum10-lookup improvement is mathematically impossible, even before the stronger enumeration baseline. Report HOLD and do not build the symbolic executor. Otherwise report that room may remain; this is not evidence the solver can exploit it. Full bridge implementation/evaluation requires completion and separate publication of its prospective protocol, including recursive preimage enumeration and current tool corpora. No criteria relaxation is allowed based on this screen.

## Inputs, targets and actual semantics

Unmodified `FiraCode-Regular.ttf` from releases5.2 and6.2 are the two primary inputs, exactly pinned in `font-input-inspection.json`. Both are actual historical releases of one font family. Source licensing at each tag is SIL OFL1.1. Other downloaded releases6/6.1 are not evaluated in this stage.

The string domain is printable ASCII U+0020..U+007E, lengths1..8. Use HarfBuzz12.3.0 through uharfbuzz0.53.2; FontTools4.60.0; Python3.14.6. Shape `latn`, default language, left-to-right. Explicitly set all present GSUB/GPOS feature tags to0 except `calt=1`. Reject a non-disabled required feature or an unexpected active top-level GSUB lookup. Do not assume that passing only `calt=1` disables other defaults.

Resolve the target lookup list through `latn` ScriptRecord → DefaultLangSys → its calt FeatureRecord(s); deduplicate in actual lookup processing order. Do not union every same-tag record across other scripts/languages. Freeze the resolved full target list before any shaping. Targets are `(fontSHA256, GSUB lookup index)`, plus ordinal and structural table hash for audit. No cross-font identity or behavior comparison is made in Stage0. This native target superset includes roots a later conservative ASCII reachability analysis might exclude (for example, the multiple-substitution dash root). Keeping those targets in N only makes the Stage0 HOLD ceiling conservative. Never remove unsupported targets after observing results to manufacture a later improvement.

Coverage means a **net change in the native glyph-ID buffer between entry and exit of a top-level target lookup**. Copy glyph IDs and cluster indices immediately from the native buffer; never inspect glyph positions during GSUB. Maintain a nested lookup stack. A lookup entered without changing glyph IDs/order/length is not covered; a temporary internal change restored before the outer exit is not covered. Positions or cluster changes alone are not GSUB glyph-effect coverage. A target that changes for one context is covered once; this does not imply rule, subtable, branch, feature-interaction or all-input coverage. Report total subtable/rule inventory separately without calling it covered.

Every message callback explicitly returns True; False may suppress native processing. Save and check ordinary untraced final output against traced output. If event nesting, target identity, feature activation, or trace data are not interpretable, record failure and stop. Do not infer coverage from model execution, a lookup name appearing in a message, or a string merely containing a target glyph.

## Existing project corpus

Use the exact5.2 and6.2 `extras/showcases.txt` and `distr/specimen.html` source files listed in `source-inspection/manifest.json`. The showcase text is a substantial project-owned operator/proof corpus (6.2 is12,066 bytes). For HTML, concatenate text within each `div.code`, decode entities and discard markup. For each contiguous printable-ASCII run from each source, generate every substring of lengths1..8, deduplicate, then order by length and Unicode lexicographic value. Every method in a possible full experiment will receive this same corpus. No manually added successful witness is allowed.

This is deliberately only a ceiling screen. It does not claim the project lacks any string, and therefore need not transcribe every PNG demonstration to support a negative result. Additional proofs, current Diffenator corpora and recursive enumeration could only strengthen the full baseline. If Stage0 does not reject, that complete inventory is mandatory before the full protocol freezes.

Record each source-derived string, origins, its native target coverage and final glyph IDs/cluster values. Apply deterministic greedy set cover to the same native results: maximize newly covered targets, tie by shortest string then lexicographic value. Record coverage at k=1,4,8,16,32,64,128 and the full selected corpus. Since the target count is below128 for these fonts, the128 cap should not prevent selecting one witness per observed target; verify this rather than assuming it.

## Controls, freeze and execution bounds

Freeze Stage0 source hashes before its first execution. Controls use clearly labeled synthetic fonts built with FontTools: (a) a single substitution changes one target; (b) an unmatched single lookup is not covered; (c) a nested contextual substitution changes the outer target; (d) two nested substitutions restore the original glyph and do not cover the outer target; (e) a zero-record contextual ignore rule blocks a later alternative; (f) input ending before required lookahead does not cover the lookup. Assert independently specified expected final glyph IDs and covered top-level IDs. Verify traced/untraced equality on every synthetic case.

Before baseline collection on each real font, check traced/untraced output equality on100 deterministic source-corpus strings, selected by seed57109 without replacement (or all if fewer). This is an oracle check, not a performance comparison. Do not reuse these checked strings' coverage/results in the timed baseline: freshly replay them inside the timed budget if reached in corpus order. Any mismatch, unexpected lookup, malformed input or ambiguity ends the screen with an error report; do not patch and silently rerun frozen code.

Then replay the existing corpus on each font, with a120-second total wall-clock budget per font including source-corpus preparation, font parsing, shaping, coverage collection, logging and selection. Shared preparation is timed once and charged in full to each font; it has a30-second cap. Reserve the final5 seconds for deterministic corpus selection and writing the terminal summary, stopping generation at the corresponding deadline. Use the predetermined shortest/lexicographic order. Limit RSS to2GiB target, terminate at2.5GiB. All incomplete/censored runs and untested strings are retained as such. A partially collected corpus can still establish a rejection ceiling if its actually retained at-most128-string selected coverage, collected and selected within the total budget, leaves fewer than10 targets on both fonts; lack of such coverage in a censored run is inconclusive. Do not interpret uncovered targets as unreachable.

Report input hashes, actual feature list, exact target denominator, control outcomes, full raw coverage, corpus-size curve and decision. Elapsed time is descriptive only; Stage0 has no solver or speed comparator. No font modifications, customer outreach, private inputs or third-party binary publication. Working downloads and source copies remain private; publish original inspection/measurement code, reproducible URLs/hashes, licensing references, aggregate counts and necessary minimal witnesses only. Any later solver stage retains the same prospective benefit test and independently reviewed stronger baselines.
