## Exact sources and limits

- [Datafold migration automation](https://www.datafold.com/data-migration-guide/automate-code-translation-validation/) and [migration-agent description](https://www.datafold.com/blog/what-is-the-datafold-migration-agent/) establish an actual commercial translation-and-validation workflow. Vendor speed statements are not independent measurements and are not used as our benefit estimate.
- [VeriEQL source](https://github.com/VeriEQL/VeriEQL) and [OOPSLA2024 paper](https://www.cs.sfu.ca/~yuepeng/pubs/oopsla24.pdf) provide direct counterexample-generation prior art. [SQLancer](https://github.com/sqlancer/sqlancer) is a necessary testing comparator.
- [Buf compatibility documentation](https://buf.build/docs/breaking/), [registry dependency mapping](https://buf.build/product/bsr/) and [pricing](https://buf.build/pricing) establish both current features and paid category. Their existence does not prove a new witness service would sell.
- [ArrowType's Diffenator2 issue72](https://github.com/googlefonts/diffenator2/issues/72) directly describes the desire to check all font OpenType features on each release and friction authoring custom proof strings. It is a2023 practitioner report, not a2026 purchase commitment.
- [WeLoveFonts font-quality service](https://welovefonts.com/pages/font-quality) describes repeated testing and fixes, custom tools, and application-level checks. [Underscore font engineering](https://underscoretype.com/services) offers production, QA, plugins and automation. These independent commercial sites substantiate an engineering-service category; no hourly fee is invented.
- [Marc Foley's business biography](https://www.pdfdiffer.com/author.html), supplied by the parent researcher, describes Google Fonts contract work on font-update testing software. [Google Fonts' historical contract advertisement](https://typedrawers.com/discussion/2054/google-fonts-freelance-font-engineering-remote-contract-summer-2017) is historical buyer-origin paid-category evidence, not a current available budget. Parent evidence is in `work/round6-parent/font-commercial-evidence.md`.
- [Diffenator3](https://github.com/googlefonts/diffenator3) is the current practical comparator, including static GPOS/outline analysis and native word comparison. Exact source inspection at commit`ba0d0b451f4435e0f381de494a1f65a6c17d72c5` found GSUB/unencoded-glyph behavior explicitly outside its static identity assertion. This is a narrow scope observation, not a claim that it cannot reveal shaping changes through its existing wordlists.
- [Shaperglot](https://github.com/googlefonts/shaperglot) checks language behavior through shaping; [Fontquant](https://github.com/googlefonts/fontquant) tests technical feature properties. [Cozens' existing shaping-test system](https://simoncozens.github.io/tdd-for-otl/) already expands authored patterns, checks expected output/forbidden glyphs/collisions and provides regression reports. A solver must add useful automatic input preparation beyond these established capabilities.

## Selected lead's present evidence boundary

The candidate has not been built or evaluated. Only source and input structure have been inspected. FiraCode is a real historical engineering artifact, but its own README describes a personally maintained free-time project; it is not being treated as a paying customer. Its12,066-byte `extras/showcases.txt` proof corpus may already saturate the coarse top-level calt lookup metric. If the native baseline leaves insufficient headroom for the prospective improvement requirement, stop without building the solver. Do not redefine top-level coverage as rule/branch coverage to rescue the idea.

The proposed purchased deliverable is a regression corpus and native snapshots for a narrowly configured feature, not a correctness certificate for a font. Intentional version changes, glyph-ID reordering and aesthetic decisions are not automatically bugs. A technically useful corpus would still require a capped, separately approved paid-demand validation experiment and independent rubric judgment.

Local evidence: `source-inspection/manifest.json` pins inspected source; `font-input-inspection.json` pins real font binaries/licenses; `structural-input-inspection.json` reports lookup types only. Raw source snapshots and downloaded archives are working material, not a blanket publication bundle.
