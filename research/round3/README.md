# Round three: integrations into paid work

The frozen v2 pursuit bar remains unchanged. Round two produced reproducible technical findings but no accepted commercial hypothesis. Discovery now begins with documented recurring work and asks whether an OSS integration can improve a defined part of that work.

- **BAS data onboarding — held:** historical public procurement prices point mapping, and public data is usable. [Schema inspection](bas/STATUS.md) found no original point names and no justified global assignment constraints beyond a strong multimodal classifier. No performance experiment ran. [Independent context review](bas-independent-review/PRE-RESULT-REVIEW.md) preserves buyer and competitor evidence.
- **MEP equipment-access options — held after failed experiment:** [results](../../experiments/mep-access/RESULTS.md) preserve 66 original roadmap runs, three transformed-graph checks and zero qualifying advantage across 12 randomized fixtures. [Independent review](mep-independent-review/REVIEW.md) verifies the complete-fixture paths but reproduces an omitted-obstacle input defect. The original protocol and code remain preserved.
- **Sewer handover acceptance — held:** [follow-up](buyer-screen/sewer-followup.md) verifies municipal requirements and an actual vendor export defect. Realistic reusable multi-artifact inputs and schema rights remain unresolved.

The [initial eight buyer screens](buyer-screen/candidate-ledger.md), [ten further screens](buyer-screen/expanded-ledger.md), and [eight physical-workflow screens](physical-screen/ledger.md) are time-ordered research notes, with overlapping domains. They are not a deduplicated candidate count; older statuses are superseded by the decisions above. Repagination remained [unexecuted](buyer-screen/repagination-status.md).

No v2 pass yet. No customer communication or purchases have occurred. A future pass would justify a named bounded validation experiment, not establish profitability or operational safety. Known algorithms and existing paid suppliers are baselines, not automatic reasons to reject a useful integration.
