# Round 2B candidate ledger

Sixteen combinations considered. Only B01/B02 were deeply researched; the others are early-screen hypotheses, not validated market findings. None is marked passed.

| ID | Combination | Decision reason |
|---|---|---|
| R2-B01 | Stateful incremental-model regression campaigns | Closest dblect roadmap explicitly includes the mechanism. Current defensibility insufficient; bounded paid study may be worthwhile but no score pass. |
| R2-B02 | Privacy-free SQL migration witnesses | Skolem already implements exact wedge. VeriEQL shortcut has noncommercial code license; own correct SQL semantics is substantial. |
| R2-B03 | Minimal safe dependency upgrade frontier | Automatic remediation and dependency solvers already cover core workflow. No measured advantage over normal resolver plus Renovate; test outcomes difficult to predict. |
| R2-B04 | PII-safe relational bug reproduction | Failure preservation does not establish anonymity. Existing masking/subsetting strong; data access and leak guarantees dominate simple integration. |
| R2-B05 | Database change lock-budget rehearsal | Measured lock durations depend on live workload; pgroll already attacks zero-downtime migration. Static plan demo would not substantiate outage reduction. |
| R2-B06 | Policy-change least-privilege witness tests | Existing policy tests/diff and formal policy analysis are close. Binding policy decisions to real application authorization is missing, and narrow paid buyer unverified. |
| R2-B07 | Coverage-weighted SBOM collection repair | Likely a feature of established SBOM management; collection completeness is not knowable from missing metadata alone. No paid niche evidence. |
| R2-B08 | Reproducible-build drift bisection | Reprotest/diffoscope already vary environments and explain diffs. Added optimizer marginal without benchmark of expensive builds and committed buyer. |
| R2-B09 | Provenance-directed test budget allocation | Coverage proxy may miss correlated failures; established state selection/lineage already does most work. No trustworthy failure probability data. |
| R2-B10 | Contract-preserving API replay minimizer | Schemathesis already builds stateful testing on Hypothesis. The proposed bridge is already the product. |
| R2-B11 | Privacy budget allocation across recurring reports | Research-heavy privacy accounting and workload-specific utility require expertise; narrow payment and operational adoption unverified. |
| R2-B12 | Schema-evolution adversarial compatibility fixtures | Strong technical testing use but no independently verified paid wedge; broad cross-engine matrix maintenance expensive. |
| R2-B13 | Deletion propagation proof packets | Canary deletion does not prove real personal-data deletion completeness. Existing privacy orchestration; legal and system boundaries unresolved. |
| R2-B14 | Uncertainty-aware flaky-test quarantine | Test intelligence/quarantine already commoditized; tests violate simple independent-stationary models. No new measured advantage. |
| R2-B15 | Binary provenance rebuild verification | Established reproducible-build and supply-chain verification architecture; packaging integration alone not a differentiated business. |
| R2-B16 | Data incident causal fault campaigns | Lineage Fuzzer already demonstrates very close mechanism; convincing value requires client model corpus and comparison with ordinary mutation tests. |
