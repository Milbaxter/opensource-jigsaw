# R2-B02 — Privacy-free SQL migration counterexamples

**Reject as a new product thesis on present evidence.** It remains technically interesting; direct competitors and a license trap materially weaken the initial idea.

Buyer: a warehouse migration consultancy reviewing mechanically or AI-translated SQL before production data access. Proposed outcome: a tiny synthetic database on which original and rewritten SQL differ, exported as a regression fixture. This transfers SMT constraint solving to migration QA. Components: [SQLGlot](https://github.com/tobymao/sqlglot) ASTs, [Z3](https://github.com/Z3Prover/z3) bounded model search, [DuckDB](https://github.com/duckdb/duckdb) concrete replay. All three primary licenses are MIT, subject to dependency and notice review.

The buyer pain and paid category are supported by [Datafold's migration validation guide](https://www.datafold.com/data-migration-guide/validate-prove-parity/), its [separately purchasable migration validation](https://www.datafold.com/faq/how-does-datafolds-pricing-work/), and the [CHG customer account](https://www.datafold.com/case-study/chg-healthcare-mysql-to-snowflake-migration/). These establish work spent on query parity; they do not establish demand for bounded synthetic witnesses.

Technical bridge: parse a narrowly supported SELECT/filter/join/aggregate subset; encode table rows, duplicates, NULL semantics, and integrity constraints as Z3 variables; assert an output difference between queries; solve within an explicit row bound; materialize the model into DuckDB; replay both queries and export confirmed witnesses. A solver result of UNSAT within a bound is not unrestricted SQL equivalence. A DuckDB replay is not validation of Snowflake, Oracle, or BigQuery dialect behavior.

Primary technical precedent [VeriEQL](https://github.com/VeriEQL/VeriEQL) already performs bounded complex-SQL equivalence verification and counterexample generation. Its code license is **CC BY-NC-SA 4.0**, verified from the repository license, so it cannot silently become the commercial OSS engine. Reimplementation using Z3/SQLGlot is substantial work, especially NULL/bag/order semantics; the research paper's license is not the code license.

The decisive competitor is [Skolem](https://github.com/NguyenTienDat377/Skolem). Its maintained repository already describes DDL + query-pair input, Z3 equivalence checking, concrete counterexample databases, CI/API/MCP integration, and billing/commercial licensing. Its AGPL-3.0 license is OSS with obligations, unlike VeriEQL's noncommercial license. Its very small public footprint does not prove commercial traction, but exact conceptual and implementation overlap defeats an absence-of-competition claim. Further commercial alternatives include Datafold and [Snowflake's migration/validation workflow](https://docs.snowflake.com/en/migrations/data-migration-and-data-validation); ordinary snapshot diffing remains a cheaper baseline for many projects.

Bounded recipe if revisited: install pinned sqlglot/z3-solver/duckdb; compare `WHERE x > 0` with `WHERE x >= 0`; derive rather than hardcode `x = 0`; concretely replay both; add nullable joins and duplicate rows only after three-valued/bag semantics are modeled. Success on the trivial predicate proves plumbing only. A meaningful benchmark requires heldout real translations, false-positive checks on equivalent rewrites, unsupported-query accounting, and comparison against Skolem/VeriEQL where licensing allows research.

Scores: novelty 3, pain 9, payment 8, feasibility 6, defensibility 3, distribution 7, evidence 8 = **63/100**, confidence 0.88. No integration demo run because close prior art was already a kill condition for the proposed generic wedge. No claim of a pass.
