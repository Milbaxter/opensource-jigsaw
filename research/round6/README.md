# Round six: data delivery and digital-production tests

No pursuit pass. The array screen stopped on workload fit; the font baseline screen executed and rejected its proposed coverage advantage. The frozen v2 thresholds and evidence gates are unchanged.

- **Scientific-array partial replicas — HOLD before prototype:** the [three-concept screen](data-infra/SCREEN.md) was followed by an [independent workload audit](workloads/WORKLOADS.md). Seven authentic ERA5 extraction cubes together require about **44.2 MiB of uncompressed logical storage**, before coordinates/container overhead. Simple per-request materialization can retain them all at an ordinary small budget. This is metadata arithmetic, not measured performance; source reads to build the copies can be much larger. No meaningful joint storage-allocation choice was established, so no optimizer experiment ran. The earlier [unfrozen design](data-infra/TEST-DESIGN.md) is preserved as chronology.
- **Font-release behavioral witnesses — HOLD after frozen baseline screen:** [Full Stage 0 results](../../experiments/font-corpus/README.md) show existing Fira Code proofs cover 98/103 and 95/101 native top-level targets using 56/55 retained strings. All 207 controls passed. Only five/six targets remain, making the preregistered ten-target improvement impossible. No solver was built. [Primary commercial/workflow notes](font-commercial-evidence.md) remain evidence of a paid task, not a reason to override the negative result.

The aim is a small decisive comparison before building a larger prototype. Known algorithms can qualify through useful measured integration; an unusual dependency list cannot.
