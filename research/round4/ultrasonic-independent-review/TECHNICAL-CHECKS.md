# Independent checking approach — prepared before execution

No tests below have been executed. They describe reviewer checks after the proposer freezes the final protocol and implementation. They must not be used to silently replace or tune the proposer's frozen success criteria.

1. Record protocol and implementation SHA256 at freeze. Preserve the initial run and every repair. Check that numerical thresholds, baselines, image grid, velocity sequence, performance exclusions and rights are set before outcomes.
2. Trace original pair IDs to the assembled time×receiver×transmitter array. Check coordinates, units, origin offsets, velocity, sound-speed factors and each FFT sign/normalization. Verify odd/even mode ordering if supported; reject unsupported sizes explicitly.
3. Identify the exact canonical spectrum. Inspect evanescent/angular masks, zero-frequency behavior, nonphysical queries, Nyquist edges, amplitude clipping and whether spectral periodicity wraps out-of-range points. The reference must use the same polynomial and coordinates, not another physical model.
4. Independently compute small direct sums from the declared coefficients, using centered integer modes and the documented type2 sign. Include ordinary interior queries, near-boundary queries, cancellation/tiny outputs, a complex impulse and translated origins. Scale absolute tolerances to a declared input norm. Do not divide by a vanishing reference and then discard the case.
5. Check that FFT padding embeds centered positive/negative modes correctly, including Nyquist conventions; cubic interpolation acts consistently on complex components and pays its prefilter cost. No per-method normalization fitted from the resulting image.
6. Check shared transmit quadrature, image extent, output coordinates and depth multiplication. Separate native upstream interpolation differences from the candidate's chosen polynomial. A perfect same-polynomial result can still produce a worse physical image.
7. Inspect physical target location against the original source, not against a candidate-generated image. Arim comparison should preserve both raw scaling and any explicitly normalized profiles. Sidelobe regions and local-maximum definition must be fixed and not exclude unexpected artifacts after seeing them.
8. Inspect per-stage and complete cold/warm times, thread settings, memory measurement units on macOS, native allocations, setup reuse and all failures/timeouts. Repeat a bounded representative command if feasible; do not rerun until a better timing appears.
9. Recompute the success decision from raw observations: fastest accuracy-passing credible baseline, required absolute as well as relative saving, all correctness gates and all resource bounds. Review the complete Pareto table, not a selected unfavorable baseline.
10. Limit inference: repeated speeds from one capture are not independent flaws; numerical tolerance is not sizing/detection qualification; homogeneous contact reconstruction does not establish arbitrary-weld or refracted-path performance; CPU savings do not establish human time or willingness to pay.

Separate reviewer-generated failure cases from the preregistered benchmark. A newly discovered input-boundary failure may restrict the supported scope or invalidate a correctness claim, but must not be quietly merged into an altered original result.
