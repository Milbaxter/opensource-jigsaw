# Independent texture implementation review — pending corrections

Static inspection only. No real asset encoding, renderer execution or performance evaluation by this reviewer. Exact checkpoint hashes are in IMPLEMENTATION-CHECKPOINT.json. The protocol remains prospective; this is not a candidate score.

The renderer uses actual Three.js GLTFLoader/KTX2Loader shaders and common camera/light setup. CP-SAT receives paid individual/pair render measurements, with greedy receiving the shared initialization. These are appropriate ingredients, but the implementation is not ready for a performance freeze until the following are resolved.

1. **Byte feasibility and domains.** `smallest()` minimizes independent image payload sizes, not serialized GLB size, whose extension/JSON overhead depends on codec mix. `runSearches()` cannot certify infeasibility from that vector's GLB, nor exclude an option because its individual substitution is over budget. Preserve all individual calibration options, charge both methods identically, and ensure over-budget probes cannot be returned as winners. The unchanged nontexture buffer floor is a valid narrow infeasibility certificate. The current CP-SAT overhead adds arbitrary 16384+1024/image padding instead of the protocol's serialization-derived bound. Establish and record an actual conservative bound across the finite declarations; distinguish search restriction from proven infeasibility.

2. **Exported artifact equivalence.** Cached texture replacement copies UV transform, sampler and color space, but actual GLB loading must be checked against it. Every sealed output needs full training-view pixel comparison before held-out evaluation, including all codec/role controls. `setup()` currently uses masked composited RGB MAE for its repeat and unchanged roundtrip check; this does not establish promised full RGBA equality. Check every RGBA byte for those deterministic controls.

3. **Binding integrity.** `fingerprint()` strips material texture indices and retains sampler state, so swapping equal-sampler textures across material roles can pass structural checks. Verify each texture slot's expected source-image identity using selected payload hashes and retain shared-image relationships; this applies especially to the independently exported SpatialPack baseline.

4. **Texture memory.** Scene disposal frees materials/geometries but not their textures, and new setup discards the variant map without disposing its contents. Actual-file loads can also accumulate image/texture resources. Deduplicate and dispose texture objects and applicable decoded sources; retain common environment resources deliberately. Record/enforce a resource limit. A full per-asset option cache can be substantial even if compressed delivery files are small.

5. **Normal mip semantics.** WebP options normalize the base level then use browser-generated mipmaps. That differs from the promised explicit normalization at every mip. WebP has no embedded mipchain; prospectively state the actual delivered behavior or provide a matching implementation without inventing unsupported delivery semantics. KTX's `--normalize` handling needs confirmation across generated mips via primary tool documentation and authored controls.

6. **Runtime accounting.** The encoding-stage deadline is checked once per image, while each option can invoke multiple 120-second external commands plus image processing. Propagate one absolute deadline and check after the final work, so the final image cannot overrun silently. Search/preset/texture and SpatialPack wrappers must enforce their declared wall budgets, with cancellation of descendants and preserved failures. The top-level orchestrator and actual SpatialPack API integration were not yet available at this checkpoint; review remains open.

No held-out views may run before all cells/methods are sealed. All adjustments above must be source/protocol frozen before actual evaluation, with failed controls retained. The proposed byte/error endpoints support a renderer-specific small case study, not measured human time, production ROI, or cross-device perceptual equivalence.

## Follow-up static findings and repairs

The researcher accepted full, equally charged individual calibration probes and retained all option domains; infeasible probes cannot win. The new serialization-derived bound takes independent maxima of image/texture JSON entries, union extension declarations, and conservative offset digit widths. This is a reasonable conservative constraint, with actual artifact-size and schema assertions; it must not be treated as a proof that no feasible allocation exists. A remaining writer-specific nonimage floor can include repackable padding and is not automatically a competitor-wide lower bound.

The renderer now hashes every full RGBA training image for cached-versus-actual sealed artifact equality, separately checks raw RGBA original repeats/roundtrips, records named source-image bindings, disposes textures and bounds its variant cache. These fix the principal image-equivalence and memory-lifecycle concerns. This does not replace executable codec/material controls.

Pinned KTX4.4.2 bundled `toktx.html` documents the encoding enum `astc | etc1s | uastc`; the original `basis-lz` argument was incorrect and has been corrected before any real encoding. That documentation also says `--normalize` forces the fourth component to 1.0. Therefore arbitrary normal alpha preservation cannot be claimed, and WebP automatic mip generation cannot be described as explicit per-mip renormalization. These require honest prospective scope wording or a matching implementation.
