# Three engineering-workflow combinations: bounded reserve screen

**No candidate is ready for performance execution.** FMU lifecycle acceptance is the strongest reserve because the practitioner pain and execution contract are unusually concrete. The missing item is a licensed failure corpus and evidence that a competent short checkpoint test is inadequate. PDF source/export parity and SPICE probe planning have plausible mechanisms but stronger unresolved differentiation/input barriers. No scores, benchmarks, binaries, or performance tests were run.

## 1. FMU lifecycle acceptance for batch and checkpointed simulations

**Proposed combination:** FMPy + Hypothesis state machines + isolated process replay. Transfer transaction/recovery testing into engineering model delivery. Read optional FMI capabilities and execute only permitted lifecycle operations. Compare an uninterrupted run against checkpoint/restart and save/detour/restore branches, then shrink any discrepancy into a short repeatable supplier ticket. Scope the report to the exact FMU bytes, importer, platform, input schedule and requested workflow; do not infer physical model accuracy.

**Specific customer problem:** A simulation integrator accepting a supplier's FMU needs to know whether repeated batch restart and checkpoint reuse work before integrating it into a long-lived system. [FMPy #812](https://github.com/CATIA-Systems/FMPy/issues/812) describes real-data batches separated by hours/days and an access violation after restoring in a new process. [FMPy #304](https://github.com/CATIA-Systems/FMPy/issues/304) reports initialization consuming 60% of one user's simulation and a restore failure before reinitialization despite passing an existing FMPy serialization test. That is a user-specific observation, not candidate ROI. The issue includes a small Dymola example and binary attachment, but redistribution/execution rights were not established here.

[OpenModelica #15216](https://github.com/OpenModelica/OpenModelica/issues/15216) documents segmentation of a long run because of memory consumption. The associated [merged fix #15915](https://github.com/OpenModelica/OpenModelica/pull/15915), merge `1ea1f7f5bce770f12484f284f36afa82f9812a37`, changes parameter preservation during restore. This is historical pain, not an untested new bug. Its parameter-change semantics require careful contract review; it cannot simply be counted as a failing unchanged-state equivalence case.

**Paid category:** [Siemens' XiL integration and testing service](https://www.siemens.com/en-us/products/vdynamics-xil-infrastructure-software-test-services-mil-sil-hil/) explicitly includes FMU integration, compatibility and regression testing. [Maplesoft FMUTester](https://www.maplesoft.com/support/help/view.aspx?path=FMUTester) documents release validation built on FMPy inside Maple/MapleSim. This establishes commercially supplied simulation integration/testing, not a public price or proven willingness to buy this narrower acceptance report. Likely reachable population: FMU-exporting tool maintainers and industrial simulation integrators listed in the FMI ecosystem; no contact or acquisition claim has been made.

**Competent baselines / prior art:**

- [The FMI validation page](https://fmi-standard.org/validation/) recommends multiple tools; static FMU Check is not the whole baseline. Include FMPy/fmusim simulation, VDM checks, reference FMUs, and existing vendor testing.
- Pinned FMPy `e42e288f448830c5f146ae334b38e91d17ff19fa` already has `tests/test_fmu_state.py`: continuation, get/set and serialization/reinstantiation for BouncingBall under FMI2/3. It checks boundary equality; it is a direct foundation/competitor. These tests currently skip aarch64-darwin, so turnkey native-host feasibility must not be assumed.
- [The 2021 paper](https://arxiv.org/abs/2106.01343) already evaluates save, random detour, restore and continuation. The core equivalence relation is prior art.
- [The 2026 AgenticMeta paper](https://arxiv.org/abs/2605.25101) derives model-specific metamorphic relations from functional specifications using LLMs and FMPy. Different scope, but no claim to invent FMU metamorphic testing is tenable.
- A strong cheap baseline is a fixed fresh-process checkpoint at several documented event boundaries plus the same output comparison. It must get the same data and workflow instructions. Merely beating a static XML checker is insufficient.

**Why the integration might still matter:** Capability-aware legal sequence generation can explore interaction failures involving nested snapshots, events, inputs and resources without writing a physical-model oracle; process isolation can expose stale pointers/resources that same-process recreation misses; shrinking can produce actionable reproducible failure traces. These are proposed mechanisms, not measured benefits. The added Hypothesis layer must earn its place over the short fixed test. A minimized trace is useful only if it reproduces a real defect and the simpler baseline does not already give an equally actionable result.

**Easy lawful inputs:** [Reference-FMUs](https://github.com/modelica/Reference-FMUs/tree/86ca571ec1ed4bbb4950a9355c2b88ff8ec2f78e) is BSD-2-Clause, with C source for BouncingBall, Resource, Stair, Feedthrough and other models. They are legitimate existing executable test models, but hand-coded conformance fixtures, not independently measured physical ground truth or a production failure corpus. Exact licenses and test sources are pinned locally. FMPy's top-level license file also includes bundled component notices; audit a final binary package separately.

**Contract gate:** Pin a released FMI version. [FMI3.0.2](https://fmi-standard.org/docs/3.0.2/) describes saved internal state and optional serialization, with capability flags and legal call states. Do not require cross-version or cross-platform checkpoint portability, do not mix unsupported optional capabilities with defects, and do not infer FMI2 behavior from an FMI3 excerpt. A changed parameter workflow is not automatically equivalent to restoration of the complete prior state.

**Status: CONDITIONAL HOLD.** Before a protocol, identify at least two legally executable real failure/correction pairs with clear lifecycle contracts; include unchanged positive models. The known issue attachments are not yet rights-cleared, #812 has no supplied FMU, and historic bugs have been inspected so cannot be called blind. Do not build a large synthetic fault-injection study merely to manufacture an advantage. The next bounded step, if selected, is rights and contract inspection of existing regression fixtures, not performance.

## 2. Source-to-PDF semantic parity at publishing release

**Proposed combination:** LibreOffice/Pandoc source structure + pikepdf/pdfminer extraction + ordered-tree alignment, with veraPDF as the conformance baseline. Transfer compiler translation-validation into a recurring publisher's document pipeline: compare known source headings, table cell associations and selected reading-order relationships with the exported tagged structure. The source can provide an oracle that a standalone PDF validator lacks. Do not claim full accessibility, alt-text adequacy, or infer correct reading order from geometry alone.

**Pain and paid category:** The [W3C reading-order technique](https://www.w3.org/WAI/GL/wiki/Techniques/PDF/Ensuring_correct_tab_and_reading_order_in_PDF_documents) explains checking exported order. A [designer's report](https://www.reddit.com/r/indesign/comments/y8c1u3/setting_reading_order_in_indesign_but_articles_and/) describes repeatedly repairing an 80-page export despite arranging its source. [axesPDF's current buy page](https://www.axes4.com/en/desktop-software/axespdf/buy) lists a one-user annual subscription at USD650/EUR549 and a Word+PDF bundle; this is exact paid document checking/remediation, not the price of our proposed pipeline.

**Strong alternatives:** [outloud](https://github.com/visionably/outloud) now advertises semantic checks beyond conformance and source-PDF comparison, local/CI operation and SARIF. Its claims were inspected, not independently verified. [Docling #4146](https://github.com/docling-project/docling/issues/4146) explicitly proposes HTML-twin parity assertions for tagged structure; this is a proposal, not proof of shipped parity. [pdf0](https://github.com/mgilbir/pdf0/blob/main/docs/pdfua.md) already reconstructs table grids and checks structural rules. Source-aware DOCX semantics could be narrower than these, but that remaining distinction has not been tied to a real missed error.

**Lawful experiment path:** Existing open converter regression fixtures with explicit repository/file licensing, and paired source/export files, could support exact semantic comparisons. A LibreOffice reported invalid tag such as #165454 is not an advantage case if veraPDF already detects it. No paired, rights-cleared export defect passing these strongest baselines was established in this bounded screen. Manually permuting tags would be a diagnostic control, not independent discovery evidence.

**Status: HOLD before implementation.** Real paid pain exists; a concrete surviving defect/corpus and necessary alignment advantage do not yet. Plain extraction + ordered text diff is also a required cheap baseline. No graph solver or LLM is justified at this stage.

## 3. Tolerance-aware functional probe selection for analog board tests

**Proposed combination:** ngspice + SciPy statistical experimental design + NetworkX or OR-Tools only if joint coverage constraints require it. Transfer active measurement selection into functional PCB diagnosis. Simulate fault families under nuisance component tolerance and ask which accessible measurements distinguish them robustly; avoid selecting a probe that separates only nominal values but overlaps under tolerance. Intended output is a small fixture-specific measurement sequence, not a physical-board reliability certificate.

**Paid workflow:** [ASTER's testability-analysis service](https://aster-technologies.com/en/products-and-services/services/testability-analysis/) offers test-strategy simulation and test-point optimization using TestWay Express. [FixturFab](https://fixturfab.com/studio/dft) offers free probe spacing/accessibility/coverage checks feeding paid fixture ordering. The latter is a particularly strong baseline for geometry and coverage; those checks should not be repackaged as a new paid product.

**Mechanism and baseline:** Robust fault discrimination could add information beyond geometric net coverage. However, compare with ordinary Monte Carlo fault dictionaries and greedy information-gain/probe selection, not just all-probes/random. A [1999 primary paper](https://repository.hkust.edu.hk/ir/Record/1783.1-77928) already gives graph-based analog fault probe selection, and a [recent paper](https://www.sciencedirect.com/science/article/pii/S0952197625033251) studies analog fault test-point selection with PSpice-generated cases. No algorithmic first claim is warranted.

**Inputs and blocker:** Public ngspice example circuits are easy simulation inputs, but do not establish actual fixture access, measured faulty-board behavior, production fault prevalence, or buyer demand for the narrower selection tool. Published supplier service descriptions are not independent practitioner complaints. No open, measured, component-fault dataset tied to accessible probe locations and a paid user's exact problem was verified. Adding fictitious manufacturing priors or purpose-built ambiguity would make an attractive toy benchmark without validating the workflow.

**Status: HOLD at source screen.** Do not prototype until a real board/test procedure and lawful measurements establish what must be distinguished and what probes cost. No licenses for a final multi-component package are claimed; only source-level FMU rights have been examined in detail.

## Recommendation

If another reserve is needed, spend one bounded read-only pass on FMU regression-fixture rights and exact lifecycle contracts. It has the clearest independent pain and a falsifiable acceptance claim. None of the three currently warrants a pursuit pass or an expensive implementation; existing products do not themselves eliminate the opportunities, but the missing advantage/input evidence does prevent a fair benchmark now.
