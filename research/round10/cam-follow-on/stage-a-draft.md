# DRAFT — endpoint/Detour development correctness screen

This draft is not authorization to execute. It must receive source-level independent review and a parent publication freeze. No new path-generation or evaluation has run. It preserves the completed round-7 HOLD and does not contain a performance or pursuit pass gate.

## Declaration and data split

The future purchased deliverable would be an offline, human-reviewed FreeCAD adaptive-link preparation extension. The intended practical benefit is lower whole-operation computation time at comparable usable-link quality. Stage A measures only whether a real Detour/Clipper2 bridge and native endpoint adapter can produce independently verified routes on existing development data. It cannot establish that practical benefit.

Use all 147 already captured round-7 requests in lexicographic workload/request order. They are explicitly seen development data. Source archive SHA256 `d9cf520f4289ff4c9161600d8a6910b3e3391422c1b8ede625daa224fc2a7d56`; exact per-request hashes will be listed before execution. Never relabel these as a holdout. No native full-kernel operation is regenerated in this stage. Fresh actual source geometry and operation selection will be separately frozen for any later confirmation.

## Fixed adapter policy proposed for review

1. Parse complete native state including XY and Z tags. Native geometry uses XY; Z remains provenance metadata. Reject nonfinite parameters, nonpositive radius/step/scale, duplicate zero-length edges, malformed rings, unsupported touching/crossing topology, more than 4,096 original boundary vertices, or input coordinates outside signed 32-bit range. Do not repair input geometry.
2. Derive native clearance `c` and endpoint trim `d` exactly as in the pinned function. Retain ratio 3 and its original direct-distance reference. Equal start/end is unsupported and falls back.
3. Erode the captured stock with the pinned native Clipper1 settings by `R+c+2` integer units. Intersect with the outward-rounded square centered on `(a+b)/2`, half-width `ratio*distance(a,b)/2 + 4`. The triangle inequality proves this crop excludes no ratio-valid route. Validate resulting topology; reject empty domains.
4. For each endpoint inside a center component, its one port is the endpoint itself. Otherwise derive angular intervals from the intersections of its radius-`d` circle with all center boundary edges. Include eight fixed compass directions and the direction toward the other endpoint. For each open interval, add its midpoint direction. Deduplicate angles at the frozen numerical tolerance; reject more than 1,024 interval/direction candidates rather than truncate them silently. Along each direction place a candidate port at distance `d+4`, rounded to the nearest integer with an explicitly implemented half-away-from-zero rule. Reject zero-length or duplicate ports.
5. A port must lie in the center region. Its connector must pass both the exact native first/last integer-trim test with clearance `c` and an independent whole-connector test at physical radius `R`. Its trimmed checked portion must independently have radius `R+c` clearance. This whole-R rule is stricter than native endpoint exemptions and may reject otherwise native-accepted proposals; counts and native discrepancies must remain visible.
6. Retain at most eight valid ports per endpoint, ordered by connector length plus straight distance to the opposite endpoint, then integer XY. This finite approximation is shared by both new planners and makes no endpoint completeness claim. The direct start–end proposal is also tested under exactly the same native and independent policies.
7. Translate the center domain to a local integer origin. Reject extents above 65,530 units or more than 60,000 vertices/triangles; do not quantize. Use pinned Clipper2 triangulation and reject its non-success statuses. Verify nondegenerate triangles, winding, matching edges/manifold adjacency, and exact signed area equal to the domain. Holes and disconnected components must be preserved.
8. Build a flat single-tile Detour mesh from the triangles with unit `cs/ch`, no off-mesh connections and no voxelization. Query all same-component port pairs. Reject partial paths, node/buffer exhaustion or wrong final polygon. Freeze node/path limits in source. Select the shortest independently verified result, counting full connector lengths. Returning no route is allowed.
9. Compare with direct-only and an optimized lazy visibility-graph A* using the same ports, domain and validators. Small synthetic domains additionally use an exhaustive visibility graph. Detour is not an exact planar shortest-path oracle. All methods receive the same deduplication and path simplification policy.
10. Every returned route must preserve endpoints, satisfy the ratio cap, pass native per-segment trimming, independently satisfy that checked portion's `R+c` clearance, and independently satisfy whole-route `R` clearance. The native original result is audited with the same independent checker and any discrepancy is reported separately. No unverified proposal is promoted to a clear link. Native fallback remains a future production option, not a way to hide a failed Stage-A candidate route.

## Controls before development records

Freeze explicit integer fixtures and expected predicates before running them: direct clear path; rectangular obstacle detour; hole with two homotopy classes; disconnected domains; outside endpoint with a valid trimmed connector; outside endpoint beyond trim reach; reversed start/end; short direct link that sets clearance zero; first segment shorter than trim; integer truncation with negative coordinates; tangent disk contact; a one-unit under-clearance; nested island/hole; touching rings; nonzero-area self-crossing ring; zero-length edge; duplicate point; nonfinite input; crop-boundary path; uint16 extent overflow; deliberately wrong triangle adjacency; missing triangle/area mismatch; Detour partial/buffer status rejection; and an output path changed after validation.

The independent Python verifier will adapt the round-7 exact orientation/Fraction-distance method, use original stock boundaries rather than trusting offsets, and reconstruct trim points independently. Native checks use the unchanged pinned `IsClearPath` implementation. Exact controls must demonstrate native C++ and Python trim-point equality, including negative-coordinate truncation and short edges. Trace-independent mesh area/topology checks must not reuse candidate adjacency as truth.

## Resource and reporting rules

Proposed limits: 10 seconds per request, 600 seconds total development execution, 2 GiB observed process-group RSS monitored as in the published resource-only amendment. Instrumentation, preprocessing, verification and rejected inputs count. No memory-perfect or real-time claim. All command/source/binary/input hashes, failed controls, unsupported records, censored requests and logs retained. A failed correctness control stops the stage; a resource abort records a hold rather than silently excluding the hard request.

Report native-success/failed counts, planner success counts, native/independent disagreement counts, every rejection reason, path lengths and actual essential-library calls. Runtime may be retained as diagnostic metadata but no speedup, statistical performance or buyer-utility conclusion is permitted from this development set. A valid bridge requires all controls and at least one genuinely nonstraight real-request Detour route passing both native and independent checks. If absent, stop and report the limited failure; do not add synthetic workload complexity to create a success.

A later full-kernel stage must freeze fresh lawful inputs, unchanged outer FindLink lead/cutting logic, final post-smoothing physical-radius clearance audits, strong whole-kernel baselines and buyer-relevant absolute/relative savings criteria before execution. It is not authorized by this draft.
